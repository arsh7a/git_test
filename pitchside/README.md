# Pitchside

A football statistics website prototype: player profiles, percentile rankings,
player comparisons and a sortable statistics database.

> Out of the box the site shows **fictional sample data**, generated by the code
> in `src/data/sample/`. It can also load **real data** (StatsBomb 2015/16 and
> PitchAPI 2021/22 onwards) on your own computer (see below). That data is
> never committed to this public repository.

## Running it on your computer

You need [Node.js](https://nodejs.org) (the "LTS" version) installed once.
Then, in a terminal opened in this folder:

```bash
npm install
```

```bash
npm run dev
```

Open the address it prints (usually http://localhost:5173) in your browser.
Press `Ctrl + C` in the terminal to stop it.

To produce the finished website files (in the `dist` folder):

```bash
npm run build
```

## How the project is organised

| Folder / file | What it contains |
|---|---|
| `src/data/types.ts` | The *shape* of the data: players, clubs, leagues, season stats. |
| `src/data/sample/` | The sample-data generator (fictional names, clubs, stats). |
| `src/data/metrics.ts` | Every statistic: its label, explanation, formula, and which stats appear on radars, percentile panels and tables. |
| `scripts/statsbomb.ts`, `scripts/pitchapi.ts` | Download each source and turn it into season data. |
| `scripts/wikidata.ts` | Player and club details and ids from Wikidata. |
| `scripts/build.ts`, `scripts/images.ts` | Merge the sources into the site's data; crests and photos. |
| `src/data/source.ts` | Chooses real data (if downloaded) or sample data. |
| `src/data/index.ts` | **The single entry point for data.** Lookups, search, percentiles, similar players, leaderboards. |
| `src/components/` | Reusable pieces: charts, tables, search box, navigation. |
| `src/pages/` | One file per page: Home, Players, PlayerProfile, Compare, Stats, Leagues. |
| `src/styles/global.css` | All colours, fonts and layout. Colours are defined once at the top for light and dark mode. |

## Real data

The site can combine two sources, each downloaded to `data-cache/` (never
committed) and merged into `src/data/real/` (also never committed):

| Seasons | Source | Leagues |
|---|---|---|
| 2015-16 | [StatsBomb Open Data](https://github.com/statsbomb/open-data) (free, no key) | Premier League, La Liga, Serie A, Ligue 1 |
| 2021-22 to today | [PitchAPI](https://pitchapi.dev) (free key, no request limit) | Premier League, La Liga, Serie A, Bundesliga, Ligue 1 |

Run whichever sources you want, then the Wikidata, build and image steps:

```bash
npm run data:statsbomb
```

```bash
PITCHAPI_API_KEY=pk_... npm run data:pitchapi
```

```bash
npm run data:wikidata
```

```bash
npm run data:build
```

```bash
npm run data:images
```

- `data:statsbomb` downloads every 2015/16 match's events (about 5 GB, a few
  minutes) and keeps a small per-player summary of each.
- `data:pitchapi` downloads per-player match stats, lineups and events for
  every finished match (about 10,000 matches; one to two hours the first time).
  Re-running fetches only new matches, so it also keeps the current season up
  to date. Keep the key out of the code: pass it as `PITCHAPI_API_KEY`.
- `data:wikidata` matches clubs and players to Wikidata by name (ambiguous
  names are skipped rather than guessed) for birth dates, heights, club
  colours, freely licensed images, and the ids that tell the build that, say,
  Messi in 2015-16 and Messi in 2021-22 are the same player.
- `data:build` merges everything into the site's data file. Each source's
  stats keep their own definitions; a stat a season's source does not measure
  shows as "—" and is left out of that season's radars, panels and tables.
- `data:images` downloads crests and photos (PitchAPI's first, then Wikimedia
  Commons; Commons photos link to their page for the author and licence).

Each `--build-only` flag (`data:statsbomb`, `data:pitchapi`) rebuilds from the
cache without downloading. Delete `src/data/real/` to go back to sample data.

**Terms.** StatsBomb (`LICENSE.pdf` in their repository): research and
non-commercial use only, no redistribution, and anything published must credit
StatsBomb with their logo (the footer does). PitchAPI publishes no terms page;
its SDK notes that access to its data is governed by its terms of service.
Because of StatsBomb's terms, keep any page built from this data private.

**StatsBomb definitions.** Minutes are scaled so a full match is 90. A few
definitions are Pitchside's own approximations: a *progressive pass* is
completed, from outside the defending 40%, at least 10 yards forward or into the
box (not corners or throw-ins); a *progressive carry* is at least 10 yards
forward ending in the opponent's half; *touches* are completed receipts, set
pieces taken, recoveries, clearances, successful interceptions and keeper
claims; *shot-/goal-creating actions* are the two attacking actions before a
shot or goal in the same possession. StatsBomb has no match ratings or
post-shot xG.

**PitchAPI definitions.** Stats are the provider's own. Its expected assists
(xA) are shown as xAG; it has no progressive actions, shot-creating actions or
tackles won. Average rating is weighted by minutes; very short substitute
appearances are often unrated, which pulls a player's average down slightly.

### How the data switch works

Every page reads data through `src/data/index.ts`; `src/data/source.ts` picks
real or sample data. Any other provider only needs to produce the `Dataset`
shape from `src/data/types.ts`, listing the stats it measures in
`availableStats`; metrics, radars, tables and leaderboards that need anything
else are left out.

## Key definitions

- **Per 90**: a stat divided by minutes played, times 90, so that players with
  different playing time can be compared fairly.
- **Percentile**: the share of players in the same position group (with at least
  900 minutes that season) that this player outperforms on a stat.
